---
name: pr
description: Use when writing a PR body.
---

- Conventional commit titles, plain language: `fix(web): new threads no longer spike CPU`.
- Body: the problem in a sentence or two, then how you fixed it.
- Briefly mention how the change was verified.
- UI changes need before/after images. Motion or timing needs a short video. If the PR is mainly about UI put the before/after images first.
- Upload PR evidence to GitHub. Never commit PR-only screenshots or assets.
- Keep the PR focused on one concern.
- Write for a reviewer who can see the diff.
- If the change has non-obvious risk, migration impact, or a meaningful blast radius, call it out explicitly.
